# План реализации v1

Термины — по [GLOSSARY.md](../GLOSSARY.md), выбор бэкенда — [ADR 0001](adr/0001-cloudflare-d1-with-shared-key.md).

## Стек

- pnpm, TypeScript, Node 24 (`.node-version`).
- Фронтенд: Vue 3 + Vite + vue-router, без UI-кита, свой небольшой CSS. Даты — нативный `<input type="date">` (на телефоне открывает системный пикер).
- Бэкенд: один Cloudflare Worker со Static Assets — отдаёт собранный SPA и `/api/*`; роутинг API на Hono. Хранилище — D1.
- Dev: `@cloudflare/vite-plugin` — Vite и Worker с локальной D1 в одном `pnpm dev`.
- Проверки: Vitest (домен — test-first), `vue-tsc`, ESLint. Скрипт `pnpm check` гоняет всё.

## Структура

```
src/
  domain/        чистый TS без зависимостей, общий для фронта и воркера
    dates.ts       CalendarDate ('YYYY-MM-DD'), сложение/разность дней и месяцев в UTC
    periods.ts     вид периода + сегодня → [начало, конец]; будущее только у произвольного
    counting.ts    дни по странам за период, будущие дни, неуказанные дни
    schengen.ts    состав зоны, окно 90/180: использовано / осталось
    russia.ts      статус за год, статус на сегодня
    validation.ts  проверка пребывания против остальных: ошибки и предупреждения
    countries.ts   список ISO-кодов, имена через Intl.DisplayNames('ru')
  worker/        API, проверка ключа, D1
  app/           Vue: экраны, компоненты, клиент API
migrations/      SQL для D1
```

Вся логика подсчёта и валидации живёт в `domain/` и покрыта тестами; Vue и Worker её только вызывают. Валидация работает дважды: в форме (мгновенная подсказка) и в Worker (истина).

## Правила домена → код

- Пребывание — `[entry, exit]` включительно; `exit = null` — открытое, тянется до сегодня.
- Дни в стране за период = число дат пребываний этой страны внутри периода; дни разных пребываний одной страны объединяются (стык не даёт двойного дня внутри страны).
- Шенген: объединение дат по всем шенгенским странам, окно `[сегодня − 179, сегодня]`, лимит 90.
- РФ: статус за год — дни в России за 01.01–31.12 ≥ 183; статус на сегодня — дни за последние 12 месяцев ≥ 183. Исключение для лечения/обучения не поддерживается — пометка в карточке.
- Последние 12 месяцев: `[addMonths(сегодня, −12) + 1 день, сегодня]`, конец месяца с клампом (29.02 → 28.02).
- Валидация, ошибки: выезд раньше въезда; пересечение с другим пребыванием (кроме стыка) — с текстом «пересекается с пребыванием во Франции 3–10 мая»; второе открытое; открытое не последнее; въезд открытого позже сегодня.
- Валидация, предупреждение: въезд или выезд позже сегодня — «это план, в текущих итогах не учитывается».

## API

Все запросы с заголовком `Authorization: Bearer <ключ>`; ключ — секрет Worker `ACCESS_KEY`. Неверный или пустой — 403.

| Метод | Путь | Что |
|---|---|---|
| GET | `/api/stays` | все пребывания |
| POST | `/api/stays` | создать; 422 с ошибками валидации |
| PUT | `/api/stays/:id` | изменить; 422 с ошибками |
| DELETE | `/api/stays/:id` | удалить |
| GET / PUT | `/api/settings` | `{ schengen: boolean }` |

D1:

```sql
CREATE TABLE stays (
  id         TEXT PRIMARY KEY,
  country    TEXT NOT NULL,     -- ISO 3166-1 alpha-2
  entry_date TEXT NOT NULL,     -- YYYY-MM-DD
  exit_date  TEXT,              -- NULL = открытое
  created_at TEXT NOT NULL
);
CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

Колонки пользователя нет: в v1 он один. В v2 с Access добавляется `user_email` и миграция проставляет его существующим строкам.

## Экраны

- **Ввод ключа** — показывается, когда ключа нет в localStorage или API ответил 403.
- **Дашборд** (`/`): выбор периода (сегменты + два поля дат для произвольного) → карточка Шенгена (если включён учёт) → карточка «Резидентство РФ» (за текущий год, на сегодня, за прошлый год) → список стран: флаг, название, дни, «включая N будущих» → строка «не указано: N дней».
- **Пребывания** (`/stays`): строка добавления сверху, ниже список по дате въезда, новые сверху, открытое первым; правка в строке, удаление с подтверждением; ошибки и предупреждения под строкой. Выбор страны — комбобокс с поиском по русскому названию. Переключатель шенгенского учёта — здесь же.

Флаги — пакет `flag-icons` (SVG): эмодзи-флаги в Windows не рисуются, показываются буквы.

## Порядок работы

1. Каркас: pnpm, Vite + Vue + TS, Worker + Hono, D1 локально, Vitest, ESLint, `pnpm check`.
2. `domain/` test-first: даты → периоды → подсчёт → Шенген → РФ → валидация.
3. Worker: миграция, CRUD, проверка ключа, валидация через `domain/`.
4. Экран пребываний.
5. Дашборд.
6. Деплой: аккаунт Cloudflare, `wrangler login`, `d1 create`, миграция, `wrangler secret put ACCESS_KEY`, `wrangler deploy`. Шаги с аккаунтом делает владелец.
7. Перед реализацией `schengen.ts` — сверить текущий состав зоны по первоисточнику (сайт Еврокомиссии).
